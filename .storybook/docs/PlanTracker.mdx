# PlanTracker UI documentation

This Storybook documents the **frontend UI layer** of PlanTracker.

## What belongs here

- Reusable UI components from `src/lib/components`
- Full-page view stories from `src/views`
- Interaction states, empty states, loading states, and error states
- Visual behaviour that is hard to inspect from the running app

## What does *not* belong here

- TypeScript module / API reference docs for `src/lib/api`, `src/lib/stores`, `src/lib/utils`, and `src/routes/**/*.ts`
- Rust backend API docs from `src-tauri/`

Those are generated separately and linked from the custom docs landing page.

## Suggested story coverage

For each reusable component, add stories for:

- Default state
- Loading state
- Empty state
- Error state
- Disabled / read-only state
- Dark/light theme variants where relevant

For each full-page view, prefer mocked stores / props so the page can render in isolation.
